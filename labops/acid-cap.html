09 · Guarantees

ACID today — CAP when we grow.

Atomicity

register_run() inserts a run and its first metric in one transaction. If the metric insert fails, the EXIT HANDLER rolls back the run insert. Verified: the rejected 24 GB-node call left the run count unchanged.

Consistency

Every commit moves the database between states satisfying all constraints: FK integrity, CHECK domains, ENUM vocabularies, and the VRAM rule raised via SIGNAL before any write.

Isolation

InnoDB's REPEATABLE READ: the lab lead's dashboard read sees a consistent snapshot even while a researcher commits new runs mid-query; concurrent register_run() calls serialise on the indexes without corrupting either insert.

Durability

With innodb_flush_log_at_trx_commit=1, a committed registration survives a crash of the host — essential when that row is the only record that a $3/hour node was occupied.

The practical lesson

The moment a read replica is added for dashboards, a network partition forces a choice — and the right answer is per-workload, not per-system:

· AP  financial queries (Q3, Q10) — staleness acceptable for minutes.

· CP  audit trail & claim verdicts — a wrong verdict read is worse than a delayed one.
