Q12 — the audit trigger live

Every status transition must be traceable. run_audit starts empty — no INSERT statement in the whole project writes to it. Only the trigger can.

CREATE TRIGGER trg_run_status_audit
AFTER UPDATE ON experiment_runs
FOR EACH ROW
BEGIN
    IF NEW.status <> OLD.status THEN
        INSERT INTO run_audit (run_id, old_status, new_status)
        VALUES (NEW.run_id, OLD.status, NEW.status);
    END IF;
END

Q13 — atomic run registration live

A run may only be registered on a node with ≥ 40 GB VRAM; the run and its first metric are inserted in one transaction. The EXIT HANDLER rolls back on any error — a half-registered run can never exist.

CREATE PROCEDURE register_run( ... )
BEGIN
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN  ROLLBACK;  RESIGNAL;  END;

    SELECT vram_gb INTO v_vram FROM gpu_nodes
    WHERE  node_id = p_node_id;
    IF v_vram < 40 THEN
        SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT =
          'Node has insufficient VRAM for a training run';
    END IF;

    START TRANSACTION;
        INSERT INTO experiment_runs (...) VALUES (...);
        INSERT INTO run_metrics
        VALUES (LAST_INSERT_ID(), p_metric, p_value);
    COMMIT;
END
